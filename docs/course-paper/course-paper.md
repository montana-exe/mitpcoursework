# Курсовая работа

**Тема:** Генетический алгоритм оптимизации маршрутов доставки  
**Дисциплина:** Методы и технологии программирования  
**Вариант:** 22  
**Технологический стек:** C++20, Python, OpenCL, FastAPI, Docker, GitHub Actions

## Введение

Задача планирования маршрутов доставки относится к числу практических задач комбинаторной оптимизации. При увеличении числа клиентов полный перебор маршрутов становится непригодным, поскольку число возможных перестановок быстро растёт. В логистических системах требуется получать допустимое решение за ограниченное время, учитывать грузоподъёмность транспорта, длительность рейса и возможность последующей интеграции с внешними сервисами.

Цель работы состоит в разработке программной системы для оптимизации маршрутов доставки на основе генетического алгоритма с C++-ядром, Python-интерфейсом и контуром GPU-ускорения на OpenCL.

Для достижения цели поставлены следующие задачи:

1. Проанализировать предметную область маршрутизации доставок и определить ограничения решаемой задачи.
2. Спроектировать модульную архитектуру системы.
3. Реализовать C++-ядро генетического алгоритма.
4. Реализовать Python API для запуска оптимизации и визуализации результата.
5. Подготовить тесты для C++ и Python-компонентов.
6. Добавить бенчмарк для сравнения CPU и GPU-контуров.
7. Подготовить контейнеризацию, CI и документацию проекта.

## 1 Аналитическая часть

Маршрутизация доставок является развитием задачи коммивояжёра. В классической постановке требуется найти кратчайший цикл, проходящий через все вершины графа. Для доставки товаров чаще используется задача маршрутизации транспорта: клиентов необходимо распределить между несколькими рейсами, а каждый рейс должен начинаться и завершаться в депо. В практической постановке дополнительно учитываются грузоподъёмность автомобиля, допустимая длительность маршрута, временные окна и сервисное время у клиента.

В настоящей работе рассматривается приближённая постановка capacitated vehicle routing problem. Каждый клиент имеет координаты и величину спроса. Автомобиль имеет максимальную грузоподъёмность. Хромосома генетического алгоритма задаёт порядок посещения клиентов, а процедура декодирования разбивает этот порядок на несколько маршрутов так, чтобы не нарушать заданные ограничения.

Среди применимых подходов можно выделить точные методы, локальный поиск, муравьиные алгоритмы, имитацию отжига и генетические алгоритмы. Точные методы дают оптимальное решение, но плохо масштабируются на больших графах. Генетический алгоритм не гарантирует глобальный оптимум, однако даёт управляемый компромисс между качеством решения и временем расчёта. Это соответствует требованиям курсового проекта, поскольку позволяет показать алгоритмическое ядро, экспериментальную оценку и возможность параллельного вычисления функции приспособленности.

## 2 Проектная часть

Система разделена на четыре основных слоя:

1. C++-ядро `routeopt_core`, реализующее представление задачи, декодирование хромосомы и генетические операторы.
2. C ABI, предоставляющий устойчивую границу между C++ и Python.
3. Python-слой, содержащий Pydantic-модели, FastAPI-приложение и визуализацию маршрутов.
4. Инфраструктурный слой: Docker, Docker Compose, GitHub Actions, тесты и бенчмарки.

Такое разделение уменьшает связность компонентов. Алгоритм можно тестировать отдельно от веб-интерфейса, а Python-слой можно запускать в режиме fallback, если нативная библиотека ещё не собрана. Для производственного варианта используется C++-библиотека, путь к которой задаётся переменной окружения `ROUTEOPT_LIB`.

Архитектурная диаграмма приведена в `docs/diagrams/architecture.mmd`.

## 3 Технологическая часть

C++20 выбран для ядра из-за требований к производительности и контроля над структурами данных. В реализации используются стандартные контейнеры, генератор псевдослучайных чисел `std::mt19937_64`, турнирная селекция, элитизм, ordered crossover и мутация перестановки.

Python выбран для прикладного слоя, поскольку он удобен для API, экспериментов и визуализации. FastAPI предоставляет OpenAPI-документацию автоматически, а Pydantic V2 выполняет строгую проверку входных данных.

OpenCL используется как технологический контур для параллельной оценки расстояний. В репозитории подготовлено kernel-ядро `fitness.cl`. В текущей реализации CPU-контур является обязательным и полностью рабочим, а GPU-контур спроектирован как расширяемый: при отсутствии OpenCL система не прекращает работу, что важно для CI и переносимости.

Docker применяется для воспроизводимой сборки. GitHub Actions выполняет сборку C++, запуск C++-тестов, установку Python-зависимостей, запуск pytest и статическую проверку Python-кода через Ruff.

## 4 Реализация

Основной класс `GeneticSolver` принимает объект `Problem`, содержащий список узлов, индекс депо, грузоподъёмность автомобиля и максимальное время маршрута. Решение представлено набором маршрутов. Каждый маршрут содержит список клиентов, суммарную загрузку, длительность и расстояние.

Хромосома является перестановкой клиентов без депо. При декодировании клиенты последовательно добавляются в текущий маршрут. Если добавление очередного клиента нарушает грузоподъёмность или ограничение времени, текущий маршрут закрывается и начинается новый. Такой способ сохраняет простую структуру хромосомы и позволяет учитывать ограничения без сложного восстановления недопустимых особей.

Функция приспособленности равна сумме расстояния и штрафа за нарушение ограничений. Элитизм сохраняет лучшие особи между поколениями. Турнирная селекция снижает вероятность преждевременного доминирования одной особи, а мутация обменом двух клиентов поддерживает разнообразие популяции.

Python-метод `NativeRouteOptimizer.optimize` преобразует Pydantic-модель в массивы `numpy`, передаёт их в C API и собирает ответ в структуру `OptimizationResponse`. Если библиотека не найдена, используется fallback-алгоритм, предназначенный для разработки API и тестов, но не для итогового сравнения производительности.

## 5 Тестирование и производительность

Для C++ предусмотрен тест `routeopt_cpp_tests`. Он создаёт малую задачу, запускает генетический алгоритм и проверяет, что все клиенты посещены, решение допустимо, а загрузка маршрутов не превышает вместимость автомобиля.

Python-тесты проверяют:

1. валидацию входных моделей;
2. корректность посещения клиентов оптимизатором;
3. работоспособность `/health` и `/optimize`.

Бенчмарк `benchmarks/benchmark_cpu_gpu.py` запускает CLI в режимах `cpu` и `gpu`, измеряет время выполнения и сохраняет JSON-отчёт. При наличии OpenCL контур может быть расширен до фактического параллельного расчёта приспособленности для всей популяции. При отсутствии OpenCL результат остаётся воспроизводимым, а отчёт фиксирует, какой backend был запрошен и какой использован фактически.

## Заключение

В результате работы разработана модульная система оптимизации маршрутов доставки. Реализованы C++-ядро генетического алгоритма, Python API, визуализация, тесты, контейнеризация, CI и бенчмарк CPU/GPU. Архитектура допускает дальнейшее развитие: подключение реальных дорожных расстояний, учёт временных окон, полноценную OpenCL-оценку популяции, хранение сценариев в базе данных и веб-интерфейс для диспетчера.

Практическая ценность проекта состоит в том, что он демонстрирует полный цикл разработки: от анализа постановки задачи до воспроизводимой сборки и автоматической проверки качества.
